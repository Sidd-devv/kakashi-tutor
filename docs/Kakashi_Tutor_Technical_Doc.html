2Problem statement

As given by the organizers, and the gap behind it.

The problem

Generic AI tutors answer questions but do not track what a student actually understands. A wrong answer can mean a knowledge gap, a wrong belief, or a careless slip, and a normal tutor treats all three the same. Teachers only find class-wide gaps after the exam.

3Our solution

A test-first tutor that explains mistakes in the student's own world, and tells the teacher how each student thinks.

1. Test with reasoning

The student picks subject and topic and takes a short NCERT-only test. For each answer they rate confidence and may explain their reasoning.

2. Learner model

Mastery per concept updates after every answer. Mistakes are typed as careless, knowledge gap, or confident misconception.

3. Explain my mistakes

The tutor reviews wrong answers in the student's interest (Marvel, cricket, anything) and re-explains differently if the student says "I didn't get that".

4. Teacher view

Per-student thinking profile and class-wide gaps with ready teaching suggestions. The tutor supports the teacher; it does not replace them.

What makes it different

Interest-based explanations

Same concept, different analogy per student. Checked by a fact-checker agent so the analogy never teaches wrong science.

Reasoning-based diagnosis

We look at why the answer was given, not just whether it was right.

Confidence calibration

"Confidently wrong" means misconception. "Unsure and wrong" means a gap. Each gets different advice.

Root-cause tracing

A weak concept is traced back to its weak prerequisite, shown on the map.

Teacher-first

Per-student "how to approach this student" guidance, and a suggested 5-minute re-teach for each class gap.

Animated concept map

A glowing, interactive map and a tutor orb. Visual, memorable, clear.

  2. Dashboard: subjects, topic list, past results, revision reminders.
  3. Pick topic (chapter and topic from the book).
  4. Test: one question at a time. Confidence rating on each, optional "explain your reasoning" box. Short: 4 to 5 questions for the demo.
  5. Results: score, plus the concept map in green, amber and red. Per question: right or wrong and why.
  6. Review mistakes: tutor explains each wrong answer in the student's interest. Student can say "explain it like a movie" or "I didn't get that".
  7. My progress: score history, mastery over time, misconceptions found, revision schedule.
  1. Login as teacher.
  2. Class overview: concept heatmap, top misconceptions ("14 of 30 think X"), at-risk students.
  3. Teaching suggestions: for each gap, what to re-teach, a short explanation, an analogy, and 2 to 3 practice questions.
  4. Student list: Student A and Student B, with last test, score and trend.
  5. Student thinking profile: mastery map, misconceptions, mistake types (careless / gap / confident misconception), confidence vs correctness, which explanation style worked, and a short "how to approach this student" note.
  6. Assign test (stretch): pick a topic and target the class's weak concepts.

PartTypeJob

Test-builder agentLLMGenerates questions for a topic from its source text only; tags concepts; distractors from known misconceptions; asks for reasoning
Validator agentLLM + string matchChecks each question's quoted source passage exists and supports the answer; rejects out-of-syllabus or too-hard items
Diagnoser agentLLMClassifies a wrong answer as careless, gap, or misconception; names the misconception
Explainer agentLLMExplains in the student's interest and tone; handles "I didn't get that" with a different angle
Fact-checker agentLLMChecks every analogy against the concept's must-stay-true facts before the student sees it
Teacher-insights agentLLMTurns class and per-student data into teaching suggestions and approach notes
Learner modelPlain codeBayesian knowledge tracing: mastery per concept after each answer

OrchestratorPlain codeCalls the agents in order and stores results
Each agent is a function with its own prompt and structured (JSON) output. This is a real multi-agent design with a lightweight orchestrator, chosen for speed. LangGraph is the production path.

Learner model

Different per student. Mastery per concept, updated after each answer. Stored in the database.

It is not a memory graph or a graph database. Memory graphs matter when facts accumulate over time (as in the meeting-agent idea). Here the structure is fixed per syllabus.

8NCERT grounding

Tests must come only from the book. No outside or hypothetical questions.

  1. Narrow input: the test-builder sees only the selected topic's source text and concepts.
  2. Strict prompt: use only the provided text; no outside knowledge; NCERT Class 10 level.
  3. Citation per question: each question quotes the passage that supports its answer.
  4. Validator: checks the quote exists in the topic text and supports the answer; drops anything out of scope or too hard.
  5. Difficulty cap: recall, understanding, simple application only.
  6. Manual review: we read the demo test by hand before presenting.
Caveat: LLMs can still leak outside facts or reword slightly. Citation plus validator reduce this a lot but not completely, hence the manual review.

The JSON stores the actual NCERT text and page references, so the results screen can say "Revise: NCERT page N".

14Scaling story (for the Q&A)

  • Today the book is pre-processed. In production a teacher uploads a book and the ingestion agent processes it in the background; topics appear when ready.
  • Large books are chunked by chapter and processed in parallel.
  • Move from SQLite to Postgres; orchestration moves to LangGraph for retries and state.
  • Add more subjects, boards and languages by adding new source books; the agents stay the same.
  • Add spaced repetition, voice input, story mode and score forecasting.
